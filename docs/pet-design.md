# 桌面悬浮宠物 — 设计

状态：**提案，未写代码**。下面是功能、交互、以及会碰到的硬约束。

> **开工前已实测过的一件事（重要）**：我原本以为这台机器透明合成不可靠，会逼出一个"挂件面板"方案。**实测结果是透明可用**，所以宠物可以真的"漂浮"在桌面上，不需要画一个方块面板。
> 测法：起了一个 `transparent(true)` 的置顶无边框窗口，左半边画不透明红块、右半边留空，然后抓屏像素。红块右侧的像素**不是**统一填充色，而是混入了无关的桌面内容（`(68,120,210)`、`(12,12,12)`）——说明留空处确实透出了底下的东西。
> 之前"透明不可靠"的印象来自**更新弹窗**：那个窗口用圆角区域裁剪（`SetWindowRgn`）而不是透明，且**桌面壳页面本身不透明**（`background: var(--ds-bg-1)`），两件事被记串了。

---

## 1. 一句话

主窗口关掉之后，桌面上留一只常驻的宠物。它能被摸、被喂，能**替你收发对话**（有新消息会说、能直接回一句），也能**接住你拖过来的文件**并把它喂给当前会话。

---

## 2. 技术形态：透明置顶异形窗口

实测确认可行，所以壳就是**最直接的那种**：

```
不透明无所谓 → 透明窗口 + 无边框 + 置顶 + 跳过任务栏
形状         → 由 CSS 决定（图片 + 透明背景），不需要 SetWindowRgn
点击         → 宠物以外的透明区域要么穿透、要么由我们自己做命中测试（见 §3.3）
```

**但有一个平台差异必须处理**：Windows 上 `transparent(true)` 的 Tauri 窗口，透明区域**默认仍然吃掉鼠标事件**（窗口是矩形，透明不等于穿透）。
- 想要"点宠物才有反应，点宠物旁边的空气 = 点桌面"，需要在透明像素上做**点击穿透**（`WS_EX_TRANSPARENT` + 动态开关，或按 alpha 动态切换）
- 我倾向 **不做点击穿透**：宠物窗口做小（贴着宠物轮廓），用户不会觉得旁边那块"空气"碍事；做了穿透反而引入"有时点得到有时点不到"的不稳定感
- 这条**建议你确认**（见 §8 决策 A）

## 3. 为什么不能直接抄 whale-girl

`whale-girl` 有一个桌面伴侣（`plugins/whale-girl/desktop/`，独立 Tauri 壳 + Node 引擎）。**它是最好的参考，但不能当基础**：

| 原因 | 说明 |
|---|---|
| **它是别人的插件** | 我们不 fork。宠物**外观**可以借用任何素材，但**壳**必须是我们自己的 |
| **它是"连上去"的架构** | 它连 DSH 的 HTTP 端点（`/state`、`/events`、`/presence`、`/interact`），需要那个插件在跑。我们要的是**壳自带**的能力，不依赖某个第三方插件装了没 |
| **它已经很重** | 那套资历/等级/称号系统加上去，就变成了重复建设 |

**所以：外观可以借鉴，机制必须自己写。**

### 3.1 RDP 约束（这条真的会咬人）
这是 RDP 会话，之前做更新弹窗时踩过：**拿不到真实前台窗口、轮询焦点无效**。当时最后的解法是用 **Raw Input（`RIDEV_INPUTSINK`）** 接"用户点了窗外"。

对宠物的影响：
- ❌ 不能靠"窗口失焦"判断该不该收气泡 → 要用点击位置判断
- ❌ 不能靠前台窗口判断"用户在用别的 app，别打扰" → 要么不做这类礼貌逻辑，要么用别的手段（比如空闲时间用 `GetLastInputInfo`）
- ✅ 抓屏在 RDP 下**可用**（上面实测就是这么做的），但**窗口不在前台时 `PrintWindow` 才可靠**，`CopyFromScreen` 会抓到别的东西——自动化测试要注意

### 3.2 三种形态

**形态 1：常驻宠物（主体）**
- 约 `160×180`，透明，置顶，跳过任务栏
- 可拖到任意位置，位置记忆（多显示器要存显示器标识）
- 平时只有宠物本体，鼠标移上去才浮出小操作提示

**形态 2：气泡（交互时出现）**
- 约 `300×380`，独立的置顶窗口，点击宠物弹出
- 内容：消息列表 / 快速回复框 / 文件队列
- 点外部或 Esc 关闭——**关闭判定走 Raw Input**（见 3.1）

**形态 3：落点（拖拽接收）**
- 把文件拖到宠物身上 → 宠物"接住"，进队列
- 透明区域的命中由我们自己算：读光标坐标 + 和宠物轮廓比对（宠物是固定图，轮廓可以预先存成一张掩码）

## 4. 功能清单

### 4.1 陪伴（基础层）
| 功能 | 说明 |
|---|---|
| 待机动画 | 眨眼、呼吸、偶尔走动/打盹 |
| 位置记忆 | 拖到哪，下次还在哪；多显示器要存显示器 id |
| 开机自启 | 可选，跟主窗口一起起来 |
| 摸头/投喂 | 点击有小反馈（不做成 whale-girl 那套等级系统，太重） |

### 4.2 对话（核心价值）
| 功能 | 说明 | 数据从哪来 |
|---|---|---|
| **新消息提醒** | 会话有新回合结束时，宠物做提示动作 + 出气泡 | 主窗口已经有的 `session-observer` 插件在报当前会话；回合结束事件需要新增 |
| **快速回复** | 气泡里一个输入框，直接往当前会话发一条 | 需要宿主的 session 服务（见 §5） |
| **状态反映** | 思考中/等批准/出错 → 对应动作 | 同上 |
| **会话切换** | 气泡里列出最近会话，点一下切主窗口过去 | 需要 session 列表 |

### 4.3 文件（差异化）
| 功能 | 说明 |
|---|---|
| **接住文件** | 拖文件到宠物 → 进队列 |
| **喂给会话** | 队列里点"发送" → 文件进当前会话（作为附件或路径引用） |
| **暂存区** | 队列可留到下次；可看到缩略图/文件名/大小 |
| **拖出来** | 从气泡把文件拖到别处（同 §3 形态 3 的难点） |

### 4.4 快捷操作
- 右键宠物 → 小菜单：打开主窗口 / 新会话 / 切换会话 / 设置 / 退出
- 和现有托盘菜单**共用一套菜单定义**，不重复实现

## 5. 对话能力怎么接 —— **已查实，可行**

宠物要和会话说话，就得有**发消息**和**读消息**的能力。三条路，我查了源码：

| 方案 | 结论 |
|---|---|
| **A. 走宿主服务** | ✅ **可行**。宿主真实暴露 `sessions`、`agents`、`agentDefaultModel` 服务（`packages/core/agent-loop`、`packages/bundle/headless` 都在用） |
| B. 注入主窗口页面代发 | ❌ **不可行**。主窗口关掉时页面就没了——和"主窗口关闭时使用"直接冲突 |
| C. 用 DSH 的 HTTP API | ⚠️ 有 `/api/sessions.*`，但要 token，且不保证稳定。留作退路 |

**A 具体能做什么**（读的是 `packages/bundle/headless` 的真实用法）：

```js
const agents   = ctx.get('agents')            // 创建/管理 agent
const sessions = ctx.get('sessions')          // 持久化、flush

const { agent } = await agents.create({ sessionId, meta, agentOptions, setup })

agent.followup(createUserMessage({ content: [...], source: { kind: 'user' } }))  // ← 发消息
await agent.whenIdle()                                                          // ← 等回合结束
agent.session.events                                                            // ← 读事件流
agent.session.seq                                                               // ← 读位置
```

所以**发消息、等回合、读事件**三件事都有官方接口，不需要啃私有 API。

**但有一个必须先验的前提**：上面这段来自 **headless bundle**（一个"自己造 agent 干活"的 CLI 场景）。宠物要的是**接入已经在跑的那个会话**，而不是新建一个。这两者用到的接口**不一定相同**——需要确认：
1. 能不能列出**当前已存在的**会话/agent（`sessions.list` 在客户端那侧见过，宿主侧名字待查）
2. 能不能往一个**已存在的**会话里 `followup`
3. 能不能订阅它的**回合结束事件**（不是轮询）

> 这三条我建议**开工前用一个最小宿主插件实测**（半天），比读源码可靠——上次做渠道页就是因为"文档有、真实 build 没有"栽过一次（客户端 `connection` 的 `api` 成员被删了）。

**在验完之前**：宠物只做 §4.1（陪伴）+ §4.4（快捷操作），那部分是纯壳内的、一定能做。

## 6. 架构

```
主窗口（关掉时隐藏，不退出）
  ├── content webview（DSH 页面）—— 关掉后不工作，所以宠物不依赖它
  └── pet 窗口（常驻，可关）
        ├── 渲染：React + 帧动画（CDN 无依赖，和 tray-menu 同构）
        ├── 壳能力：Tauri IPC（拖拽位置、显隐、开机自启）
        └── 数据：新增一个宿主半插件 plugins/dsh-desktop-pet/
              ├── ctx.webServer 挂同源路由（读会话/发消息/文件队列）
              └── 落盘：<dshHome>/pet/（位置、队列、设置）
```

**关键决定：宠物不依赖主窗口的 webview。** 主窗口关闭时 `content` 可能被销毁，所以宠物要活，它需要的能力必须来自**宿主半插件**（那条路在宿主进程里，和窗口无关）。

## 7. 关窗行为

现在的行为是"关闭 → 托盘"。加宠物后变成三态，要在设置里能选：

| 设置 | 行为 |
|---|---|
| 关闭时最小化到托盘（现状） | 无宠物 |
| **关闭时留下宠物**（新默认？） | 主窗口藏起来，宠物出现 |
| 关闭时直接退出 | 无宠物 |

**还需要约定的**：宠物开着时，`退出` 怎么走？我建议**宠物有独立的 X**，且托盘"退出"永远真的退出（不然用户找不到怎么关掉它）。

## 11. 第 1 期：实际做了什么，以及踩到的两个真 bug

**实现**：`src-tauri/src/pet.rs`（窗口、位置、落盘）、`src/pet.tsx`（宠物本体与交互）、
`src/styles.css` 的 `.pet-*` 段、托盘菜单加一项开关。

**两个在真机上才暴露、光看代码看不出来的问题**：

1. **宠物窗口没有 capability，拖拽和主题监听全被拒绝。**
   `capabilities/default.json` 的 `windows` 列表里没有 `pet`。Tauri v2 的权限是**按窗口**发的，所以
   `startDragging()`（第 1 期的核心交互）和 `listen('theme-changed')` 都会抛权限错误。
   窗口能显示、能摆位置，唯独拖不动——很容易被当成"拖拽实现写错了"。

2. **托盘菜单会把整个应用锁死。**
   `show_tray_menu` 原来在**没有菜单窗口时就地 `build()`**。建 webview 会派发到主线程并等待，
   而它的两个调用方（托盘图标事件、宠物右键命令）本来就跑在主线程上——于是主线程等自己，
   所有 IPC 挂起。这不是宠物引入的：**右键托盘图标本来就会锁死**。
   修法是把菜单窗口在启动时预建好（和更新弹窗、宠物一样），`show_tray_menu` 只负责摆位置和显示。

**顺带修掉的三处坐标问题**：

- 宠物位置改用 `PhysicalPosition` + `SystemParametersInfo(SPI_GETWORKAREA)`。原来混用逻辑像素，
  在缩放环境下会差一个系数。
- 菜单按"可见卡片"而不是"窗口矩形"做边界收拢——窗口带一圈看不见的调整边框（这里左右各 8px、
  上方 1px），按窗口矩形收拢会让卡片正好压出屏幕边缘。
- 托盘图标传来的坐标物理/逻辑混用，缩放下会摆错位置。

**实测过的**（都在运行中的应用里量过，不是看代码推的）：

| 项 | 结果 |
|---|---|
| 默认位置 | `2184,840` = 工作区右下角内缩 24px，精确吻合 |
| 位置记忆 | 拖动后落盘 `x/y/monitor`，重启回到原位 |
| 透明 | 截屏见壁纸透出；页面自身 `html/body/root` 背景均为 `rgba(0,0,0,0)` |
| 待机动画 | `pet-breathe` / `pet-blink` / 耳朵抖动三条都在跑 |
| 被摸反应 | `data-mood` 切到 `happy`，弹跳 + 腮红 + 星星 + 影子收缩，1.1s 后回待机 |
| 减弱动效 | 循环动画停、**点击反应保留**（这是刻意的取舍） |
| 拖动 | `startDragging()` 返回成功 |
| 关主窗口 | 主窗口隐藏、**应用与宠物都还在** |
| 托盘开关 | 显示/隐藏宠物都生效，状态落盘 |
| 右键菜单 | 宠物贴底时**向上展开**，可见卡片完全落在工作区内 |

**没验的**：多显示器、非 100% 缩放、以及"在宠物外面点一下菜单会不会自己收起来"
（这台机器的会话没有交互桌面，合成点击送不到窗口）。
